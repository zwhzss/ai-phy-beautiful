## 一、判定标准：什么知识点适合 3D 沉浸场景

一个知识点值得做 3D 场景，须同时满足以下**正向指标**（越多越优先）：

| 指标 | 说明 |
|---|---|
| **空间结构** (S) | 概念本体具有 2D/3D 几何（轨道、场、晶格、分子、波面、流场），旋转视角能揭示新信息 |
| **动态演化** (T) | 随时间运动/变化（振荡、流动、扩散、坍缩、碰撞），静态截图无法传达 |
| **字段可视化** (F) | 可渲染矢量/标量场（电场线、磁场、温度场、应力场、波矢） |
| **尺度跨度** (M) | 同一视图中需要同时呈现多个尺度（原子↔晶格↔器件；微观粒子↔宏观天体） |
| **多视角价值** (V) | 不同观察角度给出不同物理理解（如光锥、测地线、位错滑移面） |
| **直觉缺口** (I) | 2D 无法/难以传达，3D 能显著降低理解门槛（核心收益指标） |

**建设价值 = I 为主，S/T/F/M/V 为辅助。** 若某概念"2D 已足够直观"（如普通相图、单一速率分布曲线），即使有空间元素也降级为 🟡。

### 排除标准（→ ⚪ 不建议做 3D）
- **纯数学定理/方法**：存在性唯一性、留数定理、解析延拓等——本质是符号推导，3D 无增益且易误导。
- **历史/概念/方法论讨论**：科学史、范式转变、费米佯谬、意识难题——无物理对象可渲染。
- **纯费米估算/数量级**：估算本身是算术，非可视化现象（例外见 P28 平方-立方律）。
- **抽象代数/群论**：除非对应明确几何（SO(3)/SU(2) 表示、布洛赫球）才升 🟢。

## 六、技术实现要点（复用现有基础设施）

1. **注册表驱动**：新场景按 slug 注册进 `client/src/app/features/experiments/three-scene/scene-registry.ts` 的 `reg(slug, loader)`；`hasScene(slug)` 自动驱动 2D/3D 切换，无需改实验详情组件。
2. **场景契约**：每个场景实现 `create(ctx: SceneContext): SceneInstance`，`ctx = {THREE, scene, camera, renderer, width, height}`；返回 `{update(t, dt), dispose()}`。教学级近似须在 UI 标注"示意/教学近似"（参照 P23）。
3. **宿主复用**：`scene-host.component.ts` 已提供 rAF 循环、ResizeObserver、OrbitControls、基础光照。新场景只需聚焦几何/着色器/粒子，无需重复搭脚手架。
4. **懒加载**：`three` 仅首次进入 3D 时动态 `import()`（《架构设计.md》§6.2 L2 沉浸层），保持首屏轻量。
5. **性能预算**：粒子数、网格面数设上限；流体/湍流用粒子系统而非精确求解；提供"质量档"开关（高/中/低）。
6. **可复用模板库**（Phase 1 重点沉淀）：
   - `fieldLines`（电场/磁场/等势面）
   - `orbitSystem`（椭圆轨道+速度矢量）
   - `fluidParticles`（粒子+速度场+涡度色带）
   - `probabilityCloud`（量子概率密度体素/点云）
   - `latticeBuilder`（晶格/倒格子/费米面参数化生成）
