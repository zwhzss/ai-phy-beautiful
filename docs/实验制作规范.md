# 实验制作规范

> 对应实现：`client/src/app/features/experiments/viz/`、`server/internal/seed/`、`server/internal/ai/`

## 一、实验的组成

每个实验由三部分构成，缺一不可：

| 组成 | 存放位置 | 说明 |
|---|---|---|
| 目录条目 | `server/internal/seed/data/experiments.json` | 编号/标题/slug/分类/难度/核心概念（种子数据） |
| 可视化渲染器 | `client/src/app/features/experiments/viz/catalog/<分类>.ts` | Canvas 绘制逻辑 + 参数声明 |
| 讲解内容 | `narrations` 表 + `audio/<id>/<voice>/<line_id>.mp3` | 稿件与双音色音频（AI 生成或从原型导入） |

## 二、可视化渲染器规范

### 2.1 目录结构

```
viz/
├── types.ts        # VizDefinition / VizFrame / 参数声明 + num/str/bool 取参助手
├── registry.ts     # registerViz / getViz / vizSchema / vizInstance
├── canvas.ts       # 绘图工具：view/grid/curve/poly/circle/vec/bars/hist/matrixView/cells/scatter/rng…
├── surface3d.ts    # 参数曲面渲染（画家算法 + 光照）、3D 投影、坐标轴
└── catalog/
    ├── index.ts                 # 汇总导入（新增分类必须在这里追加 import）
    └── <分类 slug>.ts           # 每个知识分类一个文件
```

### 2.2 渲染器定义

```ts
import { defineViz, num, str } from '../types';
import { registerViz } from '../registry';
import { C, clear, grid, curve, view, footnotes, heading } from '../canvas';

const myExperiment = defineViz({
  slug: 'my-experiment',            // 必须与种子数据的 slug 完全一致
  title: '我的实验',
  animated: false,                  // true 时逐帧重绘（需自备跨帧状态 → 用 create）
  params: {                         // 参数面板据此生成；DB 的 params_schema 为空时的回退来源
    n: { type: 'range', min: 1, max: 20, default: 8, label: '项数' },
    mode: { type: 'select', options: ['A', 'B'], default: 'A', label: '模式' },
  },
  draw: (f) => {
    const { w, h, params } = f;
    const n = num(params, 'n', 8);
    const mode = str(params, 'mode', 'A');
    clear(f);
    const v = view(f, { xMin: 0, xMax: n, yMin: 0, yMax: 10, inset: 40 });
    grid(f, v, { divisions: 5, ticks: true });
    curve(f, v, (x) => Math.sin(x), { color: C.accent, lw: 2.4 });
    footnotes(f, ['说明第一行', '说明第二行']);
    heading(f, '我的实验');
  },
});

registerViz(myExperiment);
```

### 2.3 硬性约定

1. **必须调用 `registerViz`**，并在 `catalog/index.ts` 里 import 所属分类文件（否则不会注册）。
2. **`slug` 必须与种子数据一致**；数据库里的 `viz_component` 字段仅作记录，运行时按 `slug` 分发。
3. **画布逻辑尺寸由组件提供**（`w`/`h`，已处理高分屏）；不要直接读 `canvas.width`。
4. **参数一律通过 `num()/str()/bool()` 读取**，不要在渲染函数里假设参数存在（`params_schema` 可能为空）。
5. **几何类可视化用 `equalView()`**，保证「圆画出来还是圆」：
   `equalView(f, cx, cy, halfW, inset?, minHalfH?)` 会自动按画布宽高比推导纵向范围。
6. **颜色统一取 `C.xxx`**（`canvas.ts` 的配色常量），保证全局视觉一致。
7. **文字要留底衬**：用 `heading()/footnotes()`（自带半透明底），避免与图形/网格重叠。
8. **性能**：像素级分形用小步长块（2–3px）绘制；`animated: true` 的渲染器需保持在数毫秒内完成一帧。
9. **不要在渲染器里改全局状态**；需要跨帧状态请用 `create(params) => ({ draw })` 工厂形式。

## 三、参数 schema 规范

渲染器的 `params` 声明与数据库 `experiments.params_schema` 同构：

```json
{
  "n":     { "type": "range",  "min": 1, "max": 20, "default": 8, "label": "项数" },
  "mode":  { "type": "select", "options": ["A", "B"], "default": "A", "label": "模式" }
}
```

- 前端取值顺序：**数据库 schema 优先**，为空时回退到渲染器声明的参数（因此 376 个实验开箱即用）。
- `label` 用中文，会直接显示在参数面板上。

## 四、讲解稿件规范

### 4.1 结构

稿件按「小节 → 台词」两级组织，`narrations` 表字段：

| 字段 | 说明 |
|---|---|
| `experiment_id` | 所属实验 |
| `section_id` | 小节标识（如 `intro`、`concept`、`formula`、`application`、`summary`） |
| `section_title` | 小节中文标题（缺失时前端回退显示 `section_id`） |
| `line_index` | 小节内顺序（0 起） |
| `line_id` | 全局唯一标识（音频文件名即 `<line_id>.mp3`），建议 `<小节缩写>-<序号>` |
| `text` | 台词文本，直接用于字幕与 TTS |
| `duration_ms` | 音频时长（合成或导入时写入） |
| `audio_yunxi` / `audio_xiaoxiao` | `/audio/<id>/<voice>/<line_id>.mp3` |
| `animation_cfg` | 可选动画配置（见 4.2） |

### 4.2 动画配置

`animation_cfg` 在台词播放时作用到可视化画布：

```json
{ "action": "setParam", "params": { "n": 12, "mode": "B" } }
{ "action": "reset" }
```

- `reset`：清空场景参数（回到画布默认值）
- 其他动作：把 `params` 合并进当前场景参数（例如逐步放大项数、切换模式，配合讲解演示）

### 4.3 写作要求

1. 口语化、有节奏：单句建议 15–40 字（一条 TTS 音频 1.5–4 秒）。
2. 每实验建议 5–8 个小节，覆盖：开场引入 → 核心概念 → 规则/公式 → 直观印象 → 交互提示 → 实际应用 → 小结。
3. 公式在稿件中用文字描述（如「a 的平方加 b 的平方等于 c 的平方」），KaTeX 渲染交给 `formulas` 字段。
4. `line_id` 一旦生成不要随意更改（音频文件名与之绑定）。

## 五、AI 生成内容

在「管理后台 → 大模型配置」激活一个 `llm` 后，用「内容生产」页生成：

- 单个：`POST /admin/experiments/:id/generate`
- 批量：`POST /admin/experiments/generate-batch`（可按难度与数量）

生成结果写入：`description` / `params_schema` / `formulas` / `history_info` / `app_hooks` / 讲解稿件，并更新 `content_status`（`pending → generating → ready|failed`，失败原因记入 `content_error`）。

> 提示词模板见 `server/internal/ai/prompt.go`，系统提示词见 `server/internal/ai/chat.go`。

## 六、语音合成

- 音色：`yunxi`（云希·男声）、`xiaoxiao`（晓晓·女声）。
- 服务选择：按当前激活的 `tts` 类型大模型；未配置时自动使用**内置 Edge TTS（免密钥）**。
- 合成后音频落在 `audio_dir/<experiment_id>/<voice>/<line_id>.mp3`，并把 URL 写回 `narrations` 表。
- 批量：`POST /admin/narrations/synthesize-batch`（`force=false` 时跳过已存在的音频）。
