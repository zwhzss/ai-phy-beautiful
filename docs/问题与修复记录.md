## 1. AI 图形左侧内容被裁、坐标被压扁

**现象**：AI 图形里贴着边界的说明文字只显示右半截（"蓝色：T_{n}(x)…"只看得见后半段），图形整体像被压扁；同一个 3×3 的数据范围在 800×520 画布上画出来，圆会变成椭圆。

**根因**（`client/src/app/features/experiments/components/ai-graph-canvas/ai-graph-canvas.component.ts`）：

- `render2D` 直接用 `viz/canvas.ts` 的 `view()` —— 它把 x、y 各自拉伸填满画布，`[-1.5,1.5]²` 在 800×520 上 y 方向单位长度只有 x 方向的 58%。
- `text` / `point.label` 等一律按给定坐标与对齐方式绘制，`at: [-1.4, 1.3]` 这种贴边坐标按中心对齐画出去，一半落在画布外被裁。

**修正**：

- 换成同文件已有的等比视图 `equalView()`：范围完整可见、x/y 单位长度一致，按画布比例向外扩展较短的一边（图形不变形、较短方向仍填满画布，多余方向留白）。
- 新增 `clampedText()`：先按字号量宽度，溢出左边改左对齐贴边、溢出右边改右对齐贴边，比画布还长的文本用 `fillText(..., maxWidth)` 横向压缩；`point.label` 右边放不下自动换到点的左侧；`rect` / `sequence` / `pie` 的 label 一并走它。

**验证**：浏览器截图确认左侧两段说明文字完整、网格呈正方形（等比）。

## 2. 「核心公式」渲染错乱

**现象**：公式面板里的下标掉到下一行、分式没有横线、字符挤成一团（`公式本身 KaTeX 能正常渲染`，是页面上的问题）。

**根因**：`math-formula` 用 `[innerHTML]` 注入 KaTeX 输出，而 Angular 的 HTML sanitizer 属性白名单里**没有 `style`**：

```
// @angular/core 的 fesm2022/core.mjs
const VALID_ATTRS = merge(URI_ATTRS, HTML_ATTRS, ARIA_ATTRS);   // HTML_ATTRS 含 class/width/height，不含 style
```

KaTeX 的排版（`.vlist` 的 `height`/`top`、`.mspace` 的宽度、`.mfrac` 分数线）**全靠 inline style**，被整体剥掉后就退化成上面那种乱码形态。这与 KaTeX 版本、字体、CSS 引入都无关。

**修正**：`client/src/app/shared/components/math-formula/math-formula.component.ts` 注入 `DomSanitizer`，输出用 `bypassSecurityTrustHtml()`（KaTeX 默认 `trust=false`、文本会转义，注入面很小）；`html` 字段类型放宽为 `SafeHtml | string`。

**验证**：渲染后 `document.querySelectorAll('.katex [style]').length` 非 0、`.katex-error` 为 0。

## 3. 讲解稿与字幕里的裸 LaTeX 不渲染

**现象**：AI 版文稿与全屏字幕里出现 `T_{n}(x) = \cos(n \arccos x)`、`|x^{n} - p(x)| = 2^{1-n}` 这样的源码文本；个别句子只渲染了一半（`\min_{p}` 渲染了，紧跟的 `\max_{x \in [-1,1]}` 还是源码）。

**根因**：

- `InlineMathPipe` 只识别 `\command{...}` / `\command_{...}` / `\command^{...}`，识别不到 `x^{n}`、`T_{n}` 这类「非命令 + 上下标」；且同样走 `[innerHTML]`，被剥 style（问题 2 同源）。
- 提示词只要求「下标用花括号」，没有强制台词公式用 `$...$` 包裹。

**修正**：

- `client/src/app/shared/pipes/inline-math.pipe.ts` 改为：优先解析 `$...$`；其次以 `\命令` 或「符号/数字 + 上下标」为锚点，向两侧扩展到「数学字符」的边界，整段交给 KaTeX；同样 `bypassSecurityTrustHtml()`。
- `server/internal/ai/prompt.go`：系统提示词与【输出要求】都明确「台词里的数学表达式必须成对用 `$` 包裹」，并把原文含糊的「公式使用 LaTeX，不带 `$` 定界符」改写为「`formulas[].latex` 不带 `$`」，避免两处要求互相打架。

**两个坑**（改这段代码时注意）：

- **空格必须算进「数学字符」**：否则 `\min_{p} \max_{x \in [-1,1]}` 会被空格切成好几段，中间的命令露出源码。
- **`$` 定界符要一起消费掉**：`findFormula` 返回的范围必须含两侧 `$`，否则页面上会多出 `$` 字符。

**验证**：CDP 逐句抓全屏讲解字幕 —— `T_{n}(x) = \cos(n \arccos x)` 整段渲染、注入的 `$…$` 用例不再显示 `$`、无 LaTeX 残留；Console 无报错。

## 4. AI 图形里两条曲线完全重合

**现象**：`graph` 里两条 `curve` 写了同一个表达式（第二条只把自变量做了平移/缩放），默认参数下完全重合，后画的整条盖住先画的 —— 画面说明写着"蓝色：T_{n}(x)"，可蓝色根本看不见。

**根因**：模型输出问题（不是渲染器缺陷），提示词里没有「多条曲线必须不同」的约束。

**修正**：`server/internal/ai/prompt.go` 图形要求新增第 10 条：同一张图里的多条曲线必须给出不同表达式，并在 label/text 里说明哪条是哪条、颜色区分开。

## 6. TTS 把 LaTeX 源码念出来

**现象**：语音把 `$y = kx + b$ 里的 $k$ 和 $b$` 念成含 `$`、反斜杠命令、下划线的源码噪音。

**根因**：`ai.Synthesize()` 是这个项目**唯一**的 TTS 出口（`ContentService.SynthesizeForExperiment` 与 `cmd/tts-gen` 都走它），它此前把 `narrations.text` **原文**直接交给 TTS。那份原文是给学生**看**的（前端用 KaTeX 渲染）。

**修正**：新增 `server/internal/ai/tts_text.go` 的 `SpeakableText()`，在 `Synthesize()` 入口把文本转成「读法版」：

| 规则 | 例子 |
|---|---|
| 去掉 `$` / `$$` 定界符 | `$y = kx + b$` → `y = kx + b` |
| 命令换中文读法 | `\cos`→余弦、`\arccos`→反余弦、`\le`→小于等于、`\theta`→西塔、`\infty`→无穷大 |
| 结构命令 | `\frac{a}{b}`→`b 分之 a`、`\sqrt{x}`→`根号 x`、`\text{…}` 只留内容 |
| 上下标 | `x^{n}`→`x 的 n 次方`、`T_{n}`→`T n` |
| 排版命令 | `\left`、`\right`、`\quad`、`\displaystyle`… 直接丢掉 |

**关键点**：只影响送进 TTS 的文本，**不改库里的台词**（显示仍走 KaTeX 渲染原文），种子/ AI 两版的文稿与音频对应关系不变。文本里没有数学标记时函数直接原样返回。

**验证**：`go test ./internal/ai/ -run TestSpeakableText`（含真实台词「转换后不残留 `$ \ ^ _ { }`」的断言、幂等断言）；副本库 + `AUDIO_DIR` 临时目录跑真实合成接口 16/16 成功。

## 7. 商用 TTS 配置填错导致「假成功」

**现象**：首页/小学/几何图形与空间/对称与变换（`symmetry`，id=17）用商用 TTS（硅基流动）合成后播放完全没有声音；界面提示"合成完成"，「测试连接」也显示成功。生产音频目录里该实验的 34 个 AI 音频（17 句 × 2 音色）**字节数完全相同（2972727）**。

**根因**（两层，缺一层都不会发生）：

1. **配置填错**：那条 TTS 记录的 BaseURL 填的是 `https://cloud.siliconflow.cn` —— 硅基流动的**控制台网页域名**，不是 API 域名；模型名还是空的。请求 `https://cloud.siliconflow.cn/audio/speech` 拿到的是那个 SPA 的首页（HTTP 200 + `text/html`），于是 2.97 MB 的 HTML 被当成 mp3 存了下来。
2. **代码没有识破**：`ai.Synthesize()` 只判断「HTTP 2xx + 文件非空」，`synthOpenAICompatible` 只判断状态码，`testTTS` 只判断字节数 > 0；`SynthesizeForExperiment` 即使全部失败也返回 `code 0`「语音合成完成」。

**修正**：

- `server/internal/ai/tts.go`
  - `synthOpenAICompatible` 校验 `Content-Type`（不是 `audio/*` / `octet-stream` 就报错，并带上响应体摘要）；
  - 新增 `ensureAudioFile` / `audioKind`：落盘后按文件头识别 mp3/wav/ogg/m4a/flac/webm/aiff，不是音频就**删除该文件**并报错（注意：Windows 下必须先关闭文件句柄再 `os.Remove`，否则删不掉）；
  - 错误信息给出可行动提示：BaseURL 应指向厂商 API（硅基流动是 `https://api.siliconflow.cn/v1`，不是 `https://cloud.siliconflow.cn`）、模型名（如 `FunAudioLLM/CosyVoice2-0.5B`）、API Key；
  - `testTTS` 走同一条路径，所以「测试连接」现在也能当场发现问题。
- `server/internal/service/content_service.go`：`SynthesizeForExperiment` 在「一句都没成功但确有失败」时返回错误（此前返回 `code 0`）。
- `client/.../ai-teach-panel.component.ts`：合成结果提示带统计（成功 / 跳过 / 失败 + 首条失败原因），不再笼统地说"合成完成"。
- `client/.../features/admin/ai-models-panel.component.ts`
  - TTS 表单**新增「模型名称」输入**（原来只有 LLM / ASR 显示该字段，TTS 根本没法填模型名）；
  - 新增「常用平台（一键填充）」下拉（llm / tts / asr / image 四类预设，移植自 study-english / study-chinese）：选「硅基流动」自动填 `https://api.siliconflow.cn/v1` + `FunAudioLLM/CosyVoice2-0.5B`；选「Edge TTS（免费本地）」自动切到 edge 通道并清空 URL / Key。

**验证**：

- 单测 `go test ./internal/ai/ -run "TestSynthesize|TestAudioKind|TestIsAudioContentType"`：假服务返回 HTML / JSON 必报错且不留下文件；返回音频时正常成功。
- 端到端（副本库 + 临时 `AUDIO_DIR` + 本地假 TTS）：返回 `text/html` → **HTTP 502** + 错误信息含 `https://api.siliconflow.cn/v1` 提示、临时音频目录 **0 个文件**；把假服务改成返回音频 → **HTTP 200、17 句全部成功、17 个文件落盘**。
- 浏览器（CDP）：TTS 类型下表单出现「模型名称」；选「常用平台 → 硅基流动」后 BaseURL 与模型名自动填好，Console 无报错。
- `go build ./...` ✓、`npx ng build` ✓。

**影响范围**：只有实验 17 的 34 个 AI 音频是坏文件（生产库其余 16580 个 mp3 正常）。重新配置 TTS 后对实验 17 点一次「🎧 合成语音」即可覆盖（该按钮传 `force: true`）。

**补充：同一链路的第二处缺陷（音色名）**——BaseURL 修好后，「测试连接」改报 `400 {"code":20047,"message":"Invalid voice."}`。两个原因：

1. `resolveVoice` 把项目音色（`yunxi`/`xiaoxiao`）映射成 OpenAI 的 `onyx`/`nova`，而**硅基流动的 `voice` 必须写成 `<模型名>:<音色ID>`**（如 `FunAudioLLM/CosyVoice2-0.5B:alex`，只写 `alex` 会被判非法；预置音色：男声 alex/benjamin/charles/david，女声 anna/bella/claire/diana）。
2. `resolveVoice` 的优先级写反了：`table[voice]` 判断排在最前，而调用方传进来的 `voice` 永远是内部标识 `yunxi`/`xiaoxiao`，于是**配置里的「默认音色」永远不会生效** —— 用户填了厂商音色名也没用。

修正：

- `resolveVoice` 改为「配置里填的音色 > 服务商音色表 > 回退云希」；
- 新增 `voiceTableFor`：BaseURL 含 `siliconflow` 时按 `模型名:音色ID` 现场拼表（男声 alex / 女声 anna），换模型时前缀自动跟随；
- 新增 `normalizeVoiceName`：用户只填了音色 ID（如 `alex`）时自动补模型名前缀；
- 400 响应里提到 voice 时，错误信息直接提示音色该怎么写；
- 前端「默认音色」的占位提示随 provider / 地址变化（硅基流动提示 `FunAudioLLM/CosyVoice2-0.5B:alex（男）/ :anna（女）`）。

验证：单测 `TestResolveVoice` / `TestNormalizeVoiceName` / `TestSynthesizeSendsConfiguredVoice` / `TestSynthesizeVoiceErrorHint`；并用**真实硅基流动接口**（副本库 + 用户自己的 Key 跑「测试连接」）得到 `合成成功：38527 字节，约 2.2 秒`。

## 8. 模型在数值字段里裸写标识符，整份教学内容解析失败

**现象**：生成「圆锥曲线统一定义」时报 `解析教学内容 JSON 失败: invalid character 'm' in literal null (expecting 'l')`，自动修复（括号/逗号/注释/截断）都没救回来。**输出本身没有截断** —— 结构完整、正常闭合，10K 字左右。

**根因**：模型在 `graph` 的数值字段里直接写了参数名/算式（本次共 5 处）：

```
"at": [num_focus_pos, 0]
"from": [-8, num_focus_pos - num_p]
"at": [-7, num_focus_pos - num_p + 0.8]
"at": [num_focus_pos - num_p - 1, num_focus_pos - num_p]
```

JSON 解析器读到 `num_` 的 `n` 会当成 `null` 字面量的开头，读完 `n`/`u`/`l` 后遇到 `m` 就报那句错。语义上这些写法是对的（渲染器本来就支持整串表达式），只是**少了引号**。

**修正**：

- `server/internal/ai/content_normalize.go` 新增 `repairUnquotedIdentifiers`：扫描 JSON，只在**字符串之外**、且处于**值位置**（紧跟 `:` `[` `,` 之后的第一个 token）时给裸标识符/算式补引号；`true`/`false`/`null` 原样保留；合法 JSON 一字不改。
- `prompt.go` 的 `ParseContent` 把它接进候选修复链（排在 `repairUnescapedQuotes` 之前），并可继续与 `normalizeContentJSON` / `repairJSONSyntax` 叠加。
- 提示词加强（示例即模板）：系统提示词的引用规则新增「算式必须整串用引号包住」并给出正反示例（反面示例正是本次的 `[num_focus_pos - num_p, 0]`，并点明会报什么错）；【输出要求】第 10 条扩写为「数组与数值字段里禁止裸写标识符或算式」。

**验证**：`TestRepairUnquotedIdentifiers`（8 个用例，含"字符串内容不动 / true·false·null 保留 / 合法 JSON 不变 / 数字与字符串混合不受影响"）、`TestParseContentWithUnquotedIdentifiers`（按本次的真实写法走完整 `ParseContent`，断言解析成功、`at[0]` 变成字符串、`curve.fn` 没有被二次加引号）；`go build ./...` ✓、`go test ./internal/ai/` 全绿。

## 9. 安装版素材库图片全部不显示

**现象**：安装版（Wails 桌面端）打开「真实素材库」，13 张卡片的标题/来源/许可都在，**图片位置全空**（13 张一个不显示）；dev 环境（`ng serve` 4200 + 后端 8080）同一页图片正常。安装目录 `<安装目录>\assets\phy-assets.zip` 在、数据目录 `%APPDATA%\phy-beauty\assets\image\*.jpg` 也在，`/api/v1/assets` 正常返回元数据 —— 也就是「素材没解压」那个老结论解释不了。

**根因**（`server/pkg/desktop/desktop.go` 的 `Handler`）：桌面端 webview 只有一个入口 handler，它按路径前缀分流：

```go
if strings.HasPrefix(path, "/api/") || strings.HasPrefix(path, "/audio/") {
    proxy.ServeHTTP(w, r) // 反代给内嵌后端（Gin 注册了 /audio、/phy-assets 静态目录）
    return
}
// ……命中内嵌产物 → 返回文件；否则 → 回退 index.html
```

## 10. 素材卡片「查看原件 ↗」点开打不开（安装版）

**现象**：装好的版本里，素材库每张卡片下的「查看原件 ↗」点下去打不开；浏览器/新窗口地址栏是 `http://wails.localhost/phy-assets/image/sun-sdo.jpg`，提示无法访问。**注意这与问题 9 不是同一处**：卡片缩略图（同一个 `fileUrl()`）是正常的，只有这个链接坏。

**根因**（`client/src/app/features/assets/assets.component.ts`）：链接写成了 `<a [href]="fileUrl(a)" target="_blank">`。

- Wails 只拦截**主窗口**的请求：`AddWebResourceRequestedFilter("*")` 装在主窗口的 WebView2 上，`processRequest` 校验 scheme+host 等于 `http://wails.localhost/` 后才交给内嵌 AssetServer（也就是问题 9 改过的那个 `Handler`）。
- `target="_blank"` 会新建窗口。Wails v2 **没有注册 `NewWindowRequested` 处理**（源码里搜不到），WebView2 在未处理该事件时会把 URI 交给系统默认浏览器/新窗口——无论哪种，都**不在主窗口的拦截范围内**。
- 于是 `wails.localhost` 这个只存在于拦截里的主机名被交给外部，必然解析失败（本机实测 `GetHostAddresses('wails.localhost')` → `No such host`）。

一句话：问题 9 是"请求到了 handler 却被错误地回退成 index.html"，这个是"请求根本没到 handler"。

**修正**：

- 「查看原件」从 `<a target="_blank">` 改为 `<button (click)="open(a)">`，并新增**应用内查看器**遮罩：影像用 `<img>`、视频/音频用原生元素、数据集 `fetch` 文本后显示在 `<pre>`（两个 CSV 分别 203 B / 12 KB）；关闭方式为「关闭 ✕」/ 点遮罩 / `Esc`。
- 查看器页脚的外链 `source_url` **保留** `target="_blank"` —— 那是真正的外网 `https://`，新窗口打开是对的。

**验证**：

- `node node_modules\@angular\cli\bin\ng.js build` 通过（注意本机执行策略禁止运行脚本，`npx` 会因 `npx.ps1` 被拦而失败，故直接调 node；`build-release.ps1` 内部能跑是因为它自己用 `-ExecutionPolicy Bypass` 启动）。
- 检查**真正打进安装包的前端产物**（`desktop/frontend/dist/chunk-*.js`）：`viewer` / `viewer-box` / `viewer-close` / `viewer-foot` / `file-link` 类名与 `aria-label 关闭`、`正在读取…`、`原始来源 ↗`、`读取失败：` 文案都在；「查看原件」已编译为 `button` + `click` → `open(a)`；外链保留 `["target","_blank","rel","noopener",3,"href",4,"ngIf"]`。
- 新 exe 用干净 `%APPDATA%` 重跑全新安装 E2E：素材解压、JPEG 魔数、`/phy-assets/image/cmb.jpg` 逐字节一致、13 条元数据 `rel_path` 全部落盘、`/audio/*`、`startup.log` 全绿。
- **诚实说明**：查看器是 UI 交互，仓库里没有任何 `.spec.ts`（无前端测试框架），所以**"点开能显示"这一步没有自动化覆盖**。能自动证明的只是"产物里确有这段模板"以及"它用的 `<img src>` 与缩略图完全同源同路径、而缩略图路径已端到端验过"。

## 11. 部分展项「文稿（种子版）」永远是空的（振动合成与李萨如图形等 202 个）

**现象**：实验详情页的「AI 教学」面板里切到「📄 文稿（种子版）」，像 **P468 振动合成与李萨如图形** 这样的展项显示"该实验还没有种子版讲解稿。"。但同一页的讲解播放器能念出台词，`narrations` 表里也确有 5 行台词 —— 也就是说"稿子"有，"存档里的稿子"没有。

### 全量审计结论（先回答"是不是所有知识点都有文稿"）

审计脚本逐 slug 比对 `server/internal/seed/data/experiments*.json`（9 个文件，600 个展项）与全部 27 个 `*narrations*.json` 文稿种子，再比对安装库：

| 检查项 | 结果 |
| --- | --- |
| 展项总数 | 600 |
| 种子文件里缺文稿的展项 | **0** |
| 库内 `narrations` 无台词的展项 | **0**（共 4141 行） |
| 种子版存档文稿为空的展项 | **202**（编号 P399 ~ P600 连续一段） |
| 里程碑（120 个）无讲解 | **0**（840 行） |

**种子文稿本身一个都不缺**；坏的只是那 202 份「种子版内容存档」里的文稿字段。

### 根因（不是种子数据问题，是快照时序 + 幂等跳过）

两个独立机制叠在一起，把"空文稿"永久固化：

1. **种子版基线是"启动时快照"，而且只建一次**。`SeedContentBaseline` → `EnsureAllSeedVersions` 遍历所有实验，为没有 `content_versions` 行的实验建一份 `source=seed` 的存档，payload 由 `buildSeedPayload` 从**当时的** `experiments` + `narrations` 组装（`content_version_service.go`）。
2. **600 个展项的稿件是分批进入内置种子文件的**。`ImportNarrations` 写入 `narrations` 时用 `skipExisting=true`，所以"某次启动时还没有的稿件"要等后续版本的种子文件到位才会补进库 —— 而 `EnsureAllSeedVersions` 发现"这个实验已有版本行"就 `continue`，**再也不会重建那份空存档**。

实测时间线（安装库 `content_versions.created_at` 与 `narrations.created_at`）：

```
10:24:21  600 个 experiments 建行
10:24:25~28  content_versions 600 行（前 389 个的 narrations 已在库 → 快照正常）
14:24:05  剩余 202 个展项的 narrations 才写入（新版本种子文件带来的）
          ↑ 此时 202 份 source=seed 存档早已存在且文稿为空，之后每次启动都被跳过
```

所以 P399~P600 这 202 个展项（含 P468）的种子版存档里 `narration.sections` 是 `[]`，`GET /admin/experiments/:id/versions/seed/content` 返回 200 + 空数组，前端于是渲染第 75 行的兜底文案"该实验还没有种子版讲解稿。"。**AI 版还没生成时，这些展项等于完全没有稿子。**

### 修正

- `content_version_service.go`：把 payload 组装从 `createSeedVersion` 里拆出 `buildSeedPayload(expID) (string, error)`（纯计算、不落库），新增 `BackfillEmptySeedNarrations()`：
  - 只处理 `source=seed` 且 **payload 里台词行数为 0**、而该实验 `narrations` **确有行** 的存档；
  - 用 `buildSeedPayload` 重建并 `UPDATE` 回原行（保留原 `id` / `is_active`，不新建行）；
  - 已有文稿的存档（含用户手工润色、AI 覆盖过的）**一行都不碰**；重建后仍为空则保留原样（宁可不动，不能越改越差）；
  - 幂等：修好后再跑改动数为 0。
  - 有意的取舍：若某实验的 `narrations` 已被 AI 版覆盖并生效，回填会把 AI 台词写进种子版存档 —— 这只发生在本就**没有任何稿件**的展项上（空基线），"有稿"比"严格保留空快照"有用得多。
- `service/init.go`：`SeedContentBaseline` 在建基线之后调用回填并记日志，**老库升级后无需任何手工操作**。
- `pkg/desktop/content.go` + `desktop.go`：新增 `RepairSeedNarrations()`，并**在 `EnsureNarrationScripts` 之后再补一次**。桌面端的建库/建基线发生在 `InitDB` 里、稿件入库在它之后，这个顺序本身就是空文稿存档的成因；补这一步后无论顺序如何都能自愈（`startup.log` 会记 `[timing] RepairSeedNarrations(种子版文稿自愈)`）。

### 验证

## 12. 文稿里的根号只有「√」没有横线

**现象**：实验详情「AI 教学 → 📄 种子版文稿」里，**受迫振动与共振峰（P469）** 那行写的是

> 稳态解振幅 A = F₀/√((ω₀²−ω²)² + (2ζω₀ω)²)：共振峰位置略低于固有频率，阻尼越大峰越矮。

根号只剩一个 `√` 钩子、被开方数缩在括号里 —— 于是看起来"根号没有上面的横线"。

**先排除的假设（都验过，不是它们）**：

- **不是 CSS 把横线清掉了**。KaTeX 的根号横线不是 `border`，而是一段内联 `<svg><path>`（`\sqrt` 命令的 `\r@@t` 字形带横线）。实测本机打包后的 `styles-*.css` + KaTeX：3 个根号全部生成 `svg path`，分数线 `border-bottom: 1px solid`，`e2e/check-radical.mjs` 通过（见 `e2e/screenshots/radical-check.png`，横线清晰可见）。
- **不是 KaTeX 报错退化成兜底**。KaTeX 兜底（`MathFormulaComponent.fallback`）会把 `\frac`、`\omega` 之类源码一起吐出来，现象不像。
- **不是管道把它渲染坏了**：`InlineMathPipe` 只认 `\命令` 与 `$...$` 两种锚点，而这行里全是 Unicode（`√`、`ω₀²`、`ζ`），**一个锚点都没有**，所以整行原样按纯文本显示。

**根因**：台词是**朗读友好的 Unicode 数学**（`√(…)`、`F₀`、`ω₀²`、`ζ`），不是 LaTeX。全库 63 条台词含 `√`（覆盖约 50 个展项），写法一律是 `√(...)` 或 `√N`；`\sqrt` 出现 0 次、`$` 出现 0 次。管道对它无从下手，浏览器只能把 `√` 当普通字符排出来。另外 P469 的 `formulas` 字段是空的（该展项没有单独的"核心公式"卡），所以整页能看见的唯一一句公式就是这行纯文本。

**修正**（`client/src/app/shared/pipes/inline-math.pipe.ts`）：

- 新增导出函数 `unicodeMathToLatex(text)`，在管道解析公式**之前**把 Unicode 根号转成 LaTeX（`√(a+b)` → `$\sqrt{a+b}$`，`√N` → `$\sqrt{N}$`）。用 `$...$` 定界而不是裸 `\sqrt{}`，是为了让"边界扩展"不越界：裸片段会把 `= Σm` 之类的邻字一起吞进公式。
- 被开方数覆盖语料里的全部形态：括号（可嵌一层）、标识符 `LC`/`RT`/`s_min`（只吃字母数字与下标，不吞运算符）、前置负号 `√−g`、单原子 `√3`/`√μ`/`√⟨n⟩`（可带下标）。
- 安全边界：`$...$` 与 `\(...\)` 区间内一个字都不改；`$` 个数为奇数时整条不转换（避免把正文吞进定界符）；不认识的字符保持原样（最坏退化成今天的显示）。
- 同步效果：`InlineMathPipe` 同时用在**讲解播放器的字幕**上，所以字幕里的根号也一起修好了；TTS 念的是 `narrations.text` 原文（`√N`），**音频不受影响**。

**验证**：

- 单测 `client/src/app/shared/pipes/inline-math.pipe.spec.ts`：8 条断言覆盖用户报的那句、嵌套括号、多字母标识符、下标、负号、`⟨n⟩`、保护 `$...$` 内的 LaTeX、`$` 奇数不转换。`ng test --include='**/inline-math.pipe.spec.ts'` → `TOTAL: 7 SUCCESS`。
  - 顺带修了跑测试的前置问题：`tsconfig.spec.json` 的 `types` 去掉了 `"node"` —— 当前 `@types/node` 用了 TS 5.6 才有的 `IteratorObject`/`BuiltinIteratorReturn`，在 typescript ~5.3 下会报一串 d.ts 错误、karma 直接起不来。
- **真实语料逐条验证** `client/e2e/check-sqrt-conversion.mjs`：从安装库读出**全部 63 条含 √ 的台词**，走同一套转换 + 管道规则，在浏览器里真渲染：

```
含 √ 的台词: 63
全部转换且渲染出根号横线: 63 / 63
仍有未转换 √ 的: 0
KaTeX 报错的: 0
根号缺横线的: 0
```
- `client/e2e/check-radical.mjs` 守住样式侧：渲染三条典型公式（含用户这一条），断言根号数与带 `svg path` 的根号数相等、分数线是实心 `border-bottom`，并输出截图 `e2e/screenshots/radical-check.png` 供肉眼复核。

**已知未覆盖（如实说明）**：只处理了 `√`。台词里还有 `∫`、`Σ`、`∝`、`≈` 这类 Unicode 数学符号仍按纯文本显示（它们观感无损，不像缺横线的根号那样像坏了），需要时按同一套路扩展 `unicodeMathToLatex`。AI 生成侧的提示词也没强制要求写 `\sqrt{}`（管道已兼容两种写法，故未改提示词）。

## 13. AI 生成的演示图是"死"的：只有静态一瞬，不会像内置单摆那样动

**现象**：内置可视化（`simple-pendulum` 等种子版图形）是逐帧动画，摆球会摆动；而 **AI 版图形**（`app-ai-graph-canvas` 渲染的 `graph` JSON）从头到尾都是一张静止的图。学生看到的是"某一瞬间"，抽象内容（振动、波动、圆周运动、传播、碰撞…）最关键的"过程"反而看不见。

**根因（两层，缺一不可）**：

1. **渲染器没有时间维度**：`ai-graph-canvas.component.ts` 把 `graph` 一次性画完就结束，表达式只有自变量 `x`（`compile(expr)` 生成的还是 `new Function('x','y',…)`）；把 `VizFrame.t` 传给它的种子渲染器有动画，AI 渲染器没有。图元类型也缺"参数方程动图"这一档 —— 只有 `curve`（函数图象）而没有 `(x(s), y(s))` 轨迹，画不出圆周运动、轨道、李萨如这类曲线。
2. **提示词从没要求过动画**：系统提示词里"呈现原则"只有一句"用图形、实践应用、生活比喻、**动画动作**等方式呈现"，具体到 `graph` 字段的 10 条规范全是静态图元的写法，模型自然只给静态图。

**修正**：

- **客户端**（`client/src/app/features/experiments/viz/time-animation.ts`、`.../components/ai-graph-canvas/ai-graph-canvas.component.ts`）：

**本次顺带揪出的两个既有缺陷**（不是新功能引入的，是"动起来"把它们暴露了）：

1. **`parsedGraph` 每次变更检测都重新 `JSON.parse`，导致 AI 图形动画被逐帧重启**（`experiment-detail.component.ts`）。
   现象极隐蔽：播放条在、`t` 读数**永远是 0.0**、画面一动不动 —— 因为子组件的 `@Input() graph` 每轮都拿到新对象引用，
   `ngOnChanges` 被反复触发、动画时间轴被反复归零（实测 `ngOnChanges` 约 60 次/秒）。
   现在 `parsedGraph`/`parsedFormulas`/`parsedHistory`/`parsedApps` 都改成 **computed**：只在 `experiment` 信号变化时重算一次。
   修完后实测 `ngOnChanges` 只触发 1 次，`t` 正常推进（并在 pingpong 下往返）。
2. **`seg()` 是位置参数，渲染器却按选项对象调用，导致模型指定的线色/线宽全部失效**（`ai-graph-canvas.component.ts`）。
   `viz/canvas.ts` 的 `seg(f, x1, y1, x2, y2, color, lw)` 收的是位置参数，而调用处写成 `seg(..., { color, lw } as never)` ——
   `as never` 把类型检查骗过去了，颜色掉成默认的深色，在深色画布上表现为"摆杆是一根黑线、模型给的颜色看不见"。
   现在按位置参数调用，并给 `seg()` 补了 `dash` 参数（`line` 图元的 `dash` 之前同样被忽略）；
   `poly`/`circle`/`dot`/`text` 本来就是选项对象，未受影响。新增颜色像素级回归测试守住这一点。

**已知未覆盖（如实说明）**：

- 只做到"表达式与 motion 图元能随时间演化"。**没有**引入物理引擎/数值积分（`s = sin(t)` 只是表达式，不是真正的微分方程解），也不支持逐帧改变图元集合（图元数量、类型在整段动画里是固定的）。
- 动画按**同一周期循环播放**，没有做"跟讲解稿逐句同步"的动画时间轴：台词里的 `animation` 动作（`reset` / `setParam`）目前只改参数，不能指定"这一句从周期的哪个相位开始演"。全屏讲解里的 AI 图形同样会自动播放（用的是同一套渲染器）。
- 是否真的生成动画图取决于模型：提示词已把"能动的主题必须动"写成硬性要求并给了写法，但没有在解析层做"该动却没动"的强制校验（那需要判断主题是否含时间过程，机器判据不可靠）。

## 14. 「参数 num_m、num_tau 没有在图形里被引用」这个提示到底是谁的错

**现象**：对「角动量守恒」点「AI 教学 → 生成」后，界面出现提示

> 提示：参数 num_m、num_tau 没有在图形里被引用，拖动它画面不会变化，建议点「重新生成」再试一次。

**先查事实，别猜模型**。真实生成结果就存在库里，直接读出来对照（`param-panel` 的滑块 vs `graph` 的字段）：

```powershell
# 只读，不写生产库
node .reasonix\tmp\dump-numtau.mjs "$env:APPDATA\phy-beauty\phy-beauty.db"
```

`content_versions(experiment_id=49, source=ai)` 里那份 `graph` 的实际用法：

| 参数 | 在图形里的位置 | 判定 |
| --- | --- | --- |
| `num_r1` / `num_r2` | 圆的 `r`、点的 `at`、动画表达式 `"$num_r2 * cos(2*t)"` | **真联动**，拖动图形实时变 |
| `num_m` | 只出现在一句 `text` 插值里：`"I = 2m(r₁² + r₂²) = $num_m * 2 * (...)"` | 只有**文字里的数字**会变，图形形状不变 |
| `num_tau` | 图形里一次都没出现（只在讲解文字里写了「τ≠0 时 L 随时间改变」） | **完全没用到**，拖了什么都不变 |

**结论是"三方各有一份责任"，不是一个笼统的"模型不听话"**：

1. **模型确实漏了 `num_tau`** —— 它把「外力矩 τ」做成了一个滑块，却从头到尾没让图形用上它。
2. **但老提示词并没有要求过"每个参数都要用上"**，只写了「至少 2 个图元引用参数」。本例恰好满足这条（`num_r1`/`num_r2` 引用了），所以模型是**照着提示词做的**，提示词本身留了口子：允许出现"拖了没反应"的死滑块。这是**规则缺口**，不是模型违约。
3. **检测器自己也有两处该修**（下面「修正」2、3）：`num_m` 的说法与用户看到的现象矛盾（数字明明变了），而且上一条动画改动引入的 `motion` 图元字段**根本没被扫描** —— 模型若按新提示词把参数写进 `"x":"num_theta0*sin(s)"`，会被**误报**成"参数没被引用"。

**修正**：

1. **提示词补上规则缺口**（`server/internal/ai/prompt.go`）：
   - 系统提示词第 4 条新增硬性要求：**`params_schema` 里的每一个参数都至少要被一个图元引用**；逐个参数自检"它出现在哪个图元的哪个字段里"；确实无法体现在图形里的，就**把它从 `params_schema` 里删掉**，不要留死滑块。并明确"写进 `text`/`label` 只算数字会变，**不算图形联动**"。
   - 「三·六、动起来优先」补一句：**`motion` 的 `x`/`y` 里同样可以写参数名**（`"x":"num_theta0 * sin(s)"`），这是动画图最直观的联动方式。
   - 用户提示词第 6 条同步：每个参数都要被引用一次，找不到用法就删掉。
2. **检测器不再用白名单**（`server/internal/service/content_service.go`）：原来只认 `from/to/at/center/w/h/r/points/fromX/toX/fn`，漏掉了 `motion` 的 `x`/`y`/`xs`/`ys`/`span`/`sFrom`/`sTo`、`sequence` 的 `nFrom`/`nTo`、`pie` 的 `numerator`/`denominator`。改为**排除展示字段**（`text`/`label`/`color`/`fill`/`emptyFill`/`stroke`/`palette`）与**原始枚举字段**（`type`/`kind`/`mode`/`closed`/`dash`，渲染器不解析参数）的通用扫描，新增图元类型不必再回来补名单。
3. **提示语按现象分两类**（同上文件）：`只写在文字标注里（只有文字里的数字会变，图形形状不变）` 与 `在图形里完全没有用到` 分开说，不再用一句"拖动它画面不会变化"把两种情况混在一起。用户那份内容现在给出的提示是：**「参数 num_m 只写在文字标注里（只有文字里的数字会变，图形形状不变）；参数 num_tau 在图形里完全没有用到，拖动它们图形不会变化，建议点「重新生成」再试一次。」** —— 与拖动时真正发生的现象一致。
   （实现上两次踩到同一个坑：`graphUnusedParams` 是"几何字段里找不到的一切"，`graphTextOnlyParams` 是"出现在展示字段里、且不在几何字段里"，**两者方向相反**，第一版把后者写成了前者，提示语里两类参数正好互换。教训写进约定 19。）
4. **渲染器把「样式/结构类标量字段」也接上参数**（`client/.../ai-graph-canvas.component.ts` 新增 `fieldNum()`、`viz/time-animation.ts` 给 `motionState()` 加可选 `resolve` 形参）：`width` / `size` / `samples` / `resolution` / `surface.range` / `span` / `sFrom` / `sTo` / `trail` 以前都是 `el.width ?? 2` 这样**直接用原始值**，模型写 `"width": "$num_w"` 会被 canvas **静默忽略**（线宽掉回默认值，画面一模一样）。检测器现在把这些字段都算作图形联动，所以它们必须真的能解析参数，否则就成了"报了已联动、拖了却不变"。现在统一走 `numeric()`；`motionState()` 的 `resolve` 不传时保持"只认数字"的老行为（纯函数单测与旧调用方不受影响）。`MotionElement` 里这些字段的类型本来就是 `number | string`，是实现的硬转让它失效的 —— 顺带把 `size`/`width`/`samples` 的类型也从 `number` 放宽到 `number | string`。

## 贯穿性约定（改这块代码前必读）

1. **显示与朗读是两份文本**：`narrations.text` 存原文（供 KaTeX 渲染），TTS 走 `ai.SpeakableText()`。不要为了"念得对"去改库里的台词。
2. **任何注入 KaTeX 输出的地方都必须绕过 Angular sanitizer**（`bypassSecurityTrustHtml`），否则 inline style 被剥、公式必然错乱。当前涉及 `MathFormulaComponent` 与 `InlineMathPipe`。
3. **提示词与示例是模型模板**：改要求要同时改系统提示词、用户提示词【输出要求】与【JSON 结构】示例，否则模型不会照做。
4. **改了生成/合成规则后，已有内容不会自动变**：提示词只影响下一次生成；音频需要重新点「🎧 合成语音」（前端传 `force: true`，会覆盖 AI 版音频，种子版音频不受影响）。
5. **AI 图形坐标是等比视图**：`axes` 给出的范围完整可见，较短的一边按画布比例向外扩展，所以长宽比不一致时会有留白，这是有意的（避免圆变椭圆）。
6. **验证纪律**：涉及写数据的验证一律用**副本库**（`DB_PATH` 指向临时副本）+ 临时音频目录（`AUDIO_DIR`），跑完删除；生产库 `%APPDATA%\phy-beauty\phy-beauty.db` 与 `server/data/audio` 不得写入。
7. **改完必编译**：前端 `npx ng build`、后端 `go build ./...` + 相关包 `go test`；UI 改动在浏览器走一遍并看 Console。
8. **生成/合成类接口不能用「HTTP 200 + 结果非空」当成功判据**：商用服务的 BaseURL 填错时常常返回 200 + 网页 HTML，必须校验产物本身（这里是音频文件头）；失败要报错、要删掉无效产物，绝不能让界面显示"完成"。
9. **桌面端不要用 `target="_blank"` 打开同源文件**（`/phy-assets`、`/audio` 这类）：`wails.localhost` 只存在于 Wails 主窗口的请求拦截里，新窗口与系统浏览器一律解析不了；同源文件要在应用内渲染或播放。`<a target="_blank">` 只用于真正的外网 `https://` 链接。同源资源的"打不开"要区分两种：请求没到 handler（本节问题 10）vs 到了却被回退成 HTML（问题 9）。
10. **种子版存档会随每个版本追加的种子数据"过时"**：`content_versions(source=seed)` 是启动时快照且**只建一次**，而展项/稿件是分批进内置种子文件的。凡是"库内容变了但存档不会自动重建"的设计，都要配一条**有判据的自愈回填**（判据要小到只碰真正残缺的行、幂等、有单测 + 真库副本验证）。加新展项/新稿件时，顺手确认 `BackfillEmptySeedNarrations` 覆盖得住（问题 11）。
11. **"有稿子"与"存档里有稿子"是两回事**：排查"某个知识点没有文稿"先分清三层 —— 种子文件有没有该 slug、库表有没有行、**版本存档 payload 里有没有内容**。前端「📄 文稿（种子版）」读的是第三层（`GET /admin/experiments/:id/versions/:source/content`），不是 `narrations` 表。
12. **台词是"朗读友好"的 Unicode 数学，不是 LaTeX**：`narrations.text` 里写的是 `√(…)`、`F₀`、`ω₀²`，不是 `\sqrt{}`。要排版就得先在 `InlineMathPipe` 里转（`unicodeMathToLatex`），别指望 KaTeX 认 Unicode。判断"公式没渲染"时先看**有没有锚点**（`\命令` 或 `$...$`）—— 一个锚点都没有的整行，管道本来就会原样输出。同理，`√` 缺横线不等于 CSS 坏了：KaTeX 的根号横线是 `<svg><path>`，不是 `border`。
13. **`viz/canvas.ts` 的绘图函数参数形态有两套，别混**：`seg` / `vec` 是**位置参数**（`color` 在第 6 位），`poly` / `circle` / `dot` / `text` / `curve` 收**选项对象**。传错不会报错（颜色、线宽静默掉默认值），**绝不要用 `as never` 把类型错误压掉** —— AI 图形里那根"看不见的摆杆"就是这么来的。改完随便画个带颜色的图元，用像素计数断言颜色真的出现（见 `ai-graph-canvas.component.spec.ts` 的"图元颜色与线宽真的生效"）。
14. **JSON 字符串字段不要在模板里用 getter 现解析**：`parsedGraph` 这类 getter 每次变更检测都 `JSON.parse` 出一个新对象，会让子组件 `@Input()` 的引用每轮都变、`ngOnChanges` 反复触发；对逐帧动画的组件就是"动画被逐帧重启、`t` 永远是 0"。库里的 JSON 字段（`graph`/`formulas`/`history_info`/`app_hooks`/`params_schema`）一律用 `computed` 缓存。**排查"画面在动但时间不走"时，先看父组件有没有给子组件喂新引用。**
15. **AI 版内容验证用 `cmd/e2e-inject-ai` 造夹具**：把符合提示词写法的内容写进**副本库**并置为生效版本（同时按 `applyContent` 的做法把教学字段写进 `experiments` 行 —— 只写 `content_versions` 的话 `content_source` 是 ai、`graph` 却是空，页面只会显示「AI 版暂无图形数据」）。真实 LLM 生成不可复现，端到端验证靠这个夹具 + `e2e/check-ai-animation.mjs`。
16. **用户报"AI 生成得不对"时，先把那次生成的真实产物读出来再下结论**：`content_versions.payload`（`experiment_id` + `source='ai'`）里存着完整 JSON，`experiments.params_schema` 存着参数面板 —— 两者对照就能分清"模型违约 / 提示词没写清 / 检测器误报"。**只读生产库**（`.reasonix/tmp/` 下有 `dump-numtau.mjs` 这类一次性脚本），别只凭提示语反推模型行为。**凡是"检测器报错"的 bug，都要同时问一句：是真违约，还是判据漏了字段？**这类判据尤其容易漏：新增图元类型/新字段名后，扫描用的白名单不会跟着长（问题 14）。
17. **"参数联动"有两个层次，别混**：**图形联动**（形状/位置/尺寸/曲线随参数变）与**文字插值**（`text`/`label` 里的 `$参数名` 换成数字）。检测器判的是前者，因为后者拖参数只让画面上的数字变一变。写提示词、写提示语、写判据时都要说清是哪一个层次。
18. **"服务端判为联动"与"渲染器真的会解析"必须同时成立**：`graphInteractiveFields`（排查参数是否为死滑块）用的是**排除展示字段**的黑名单，所以任何非展示字段都算"会影响画面"。新增/修改图元字段时，渲染器必须让该字段走 `numeric()`/`compile()`/`scalar()`（标量样式字段用 `fieldNum()`）——**不能让模型写的 `$参数名` 被 canvas 静默忽略**。两边的口径一旦分家，就会出现"提示说已联动、用户拖了没反应"（问题 14）。
19. **提示语里的分类要按"分句"写测试，整句 `Contains` 会放过方向写反**：问题 14 的两句提示（"只写在文字标注里" / "在图形里完全没有用到"）判据方向相反，第一版把两者的集合算反了，而测试只检查"整条消息里出现过这两个参数名和这两个关键词"，**全绿通过**。这类"两个互补集合"的断言必须先把消息拆成子句（`splitCoverageWarning`），再断言"哪个参数在哪一句里、不在哪一句里"。类似的还有：正例反例都要写（本批用例里用 `num_never` 做"真没用到的仍要报"的反向保护）。
