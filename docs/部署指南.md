# 部署指南

> 对应实现：`server/internal/config/config.go`、`server/internal/router/router.go`、`desktop/`、`server/pkg/desktop/`

## 一、环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| Go | 1.21+ | 后端与桌面端 |
| Node.js | 18+ | 前端构建 |
| Wails CLI | v2.12+ | 仅桌面端打包需要（`go install github.com/wailsapp/wails/v2/cmd/wails@latest`） |
| NSIS | 3.x | 仅生成 Windows 安装包需要（`makensis`） |

运行时依赖：**WebView2 Runtime**（Windows 10/11 已内置；安装包内已附带引导程序 `MicrosoftEdgeWebview2Setup.exe`，缺失时自动提示安装）。

## 二、开发运行

```powershell
# 后端（默认 http://localhost:8080，配置见 server/config.yaml）
cd server
go mod download
go run ./cmd/server

# 前端（http://localhost:4200，代理到后端）
cd client
npm install
npm run dev
```

> `start-dev.bat` 可一键启动两端。

## 三、生产部署（单进程，推荐）

后端可直接托管前端构建产物，实现「一个进程 + 一个端口」的部署。

```powershell
# 1) 构建前端（production 配置：API 走同源相对路径 /api/v1）
cd client
npm ci
npx ng build            # 产物：client/dist/phy-beauty-client/browser

# 2) 构建后端
cd ../server
go build -o phy-beauty-server.exe ./cmd/server

# 3) 启动（配置静态目录后，后端同时提供 SPA 与 API）
$env:APP_ENV       = "production"
$env:SERVER_PORT   = "8080"
$env:STATIC_DIR    = "..\client\dist\phy-beauty-client\browser"
$env:JWT_SECRET    = "<请改成随机长字符串>"
.\phy-beauty-server.exe
```

浏览器打开 `http://<主机>:8080` 即可；前端路由（如 `/experiment/collatz`）由后端回退到 `index.html`。

### 配置优先级

`环境变量 > server/config.yaml > 内置默认值`。常用环境变量：

| 变量 | 说明 |
|---|---|
| `SERVER_PORT` | 监听端口（默认 8080） |
| `APP_ENV` | `development` / `production` |
| `STATIC_DIR` | 前端构建产物目录（设置后由后端托管 SPA） |
| `DB_PATH` | SQLite 文件路径（默认 `data/phy_beauty.db`） |
| `AUDIO_DIR` | 讲解音频目录（默认 `data/audio`，经 `/audio` 对外提供） |
| `JWT_SECRET` | JWT 签名密钥（**生产必须修改**） |
| `JWT_EXPIRATION` | 令牌有效期（默认 `720h`） |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` / `ADMIN_EMAIL` | 首次启动自动创建的管理员 |

## 四、桌面端（Wails + NSIS，需求 7）

桌面端把前端产物**内嵌进 exe**，并在进程内启动同一个后端，数据落在用户目录（避免安装目录不可写）。

### 4.1 数据目录

```
%APPDATA%\phy-beauty\
├── phy-beauty.db          # SQLite 数据库
├── audio\                 # 讲解音频（首次启动自动解压）
│   ├── <experiment_id>\<voice>\<line_id>.mp3    # 展项讲解
│   └── ms<milestone_id>\<voice>\<line_id>.mp3   # 数学史/物理史里程碑讲解
├── assets\                # 素材资产（图片/数据集，首次启动自动解压）
│   ├── image\*.jpg
│   └── dataset\*.csv
├── .narration-audio.ok     # 音频解压完成标记（含归档指纹，归档升级后自动重新补齐）
├── .phy-assets.ok          # 素材解压完成标记
└── config.yaml             # 可选：覆盖默认配置（不存在则用内置默认值）
```

### 4.2 讲解与素材的自动导入

安装包内置 **600 个展项 + 120 个里程碑，共 4981 行台词、9962 个双音色音频文件（约 421 MB）
以及 13 份素材资产**，首次启动自动完成，无需联网：

1. **稿件入库**（同步，很快）：内置稿件写入 `narrations` / `milestone_narrations` 表；
2. **音频解压**（后台执行，不阻塞窗口显示）：`<安装目录>\assets\narrations-audio.zip`
   解压到 `%APPDATA%\phy-beauty\audio`；
3. **素材解压**（后台执行，体积很小）：`<安装目录>\assets\phy-assets.zip`
   解压到 `%APPDATA%\phy-beauty\assets`。

三个步骤都**幂等**：已有讲解的实验会被跳过（不覆盖用户或 AI 生成的内容）；解压对
「已存在且大小一致」的文件直接跳过，全部成功后才写完成标记（标记内含归档指纹，
归档升级后会重新扫描并只补新增部分）。

> 归档路径可用环境变量 `NARRATION_ARCHIVE` / `PHY_ASSETS_ARCHIVE` 覆盖；
> 归档不存在时跳过对应初始化（音频此时可在管理后台用 TTS 生成）。

#### 为什么归档里要带 manifest.json

归档内路径是 `<slug>/<voice>/<line_id>.mp3`，但落盘目录既可能是展项目录
（`<experiment_id>`）也可能是里程碑目录（`ms<milestone_id>`）：

- 有 **21 个 slug 既是展项又是里程碑**（例：`mass-energy-equivalence` 既是实验 126
  又是里程碑 ms13），只按 slug 反查实验 id 会把里程碑音频写进展项目录，
  前端请求 `/audio/ms13/...` 就会 404；
- 同名 slug 的两侧即使 `line_id` 相同，**台词文本也不同**（是两段不同的讲解），
  因此同一句 `line_id` 会有两份内容不同的音频，里程碑侧在归档内以
  `<slug>/<voice>/<ms-id>.<line>.mp3` 消歧。

`cmd/audio-pack` 生成的 `manifest.json` 逐文件记录落盘目录，解压时按清单直取，
结果与打包机一致、与运行库的 id 无关。

### 4.3 构建

```powershell
# 一键全流程（推荐）：自动生成并校验音频/素材归档 → 前端 → 后端 → 桌面端 → 安装包
.\build-release.bat
```

手工分步执行：

```powershell
# 1) 构建前端并复制到桌面端工程
cd client
npx ng build
Remove-Item ..\desktop\frontend\dist\* -Recurse -Force -ErrorAction SilentlyContinue
Copy-Item dist\phy-beauty-client\browser\* ..\desktop\frontend\dist\ -Recurse -Force

# 2) 生成音频归档（必须来自与实际一致的库，否则 slug→id 映射会错）
cd ..\server
go run ./cmd/audio-pack `
  -db  "$env:APPDATA\phy-beauty\phy-beauty.db" `
  -audio "data\audio" `
  -out "..\desktop\assets\narrations-audio.zip" `
  -report "..\desktop\assets\narrations-audio.report.json"
# 安装前自检归档：清单/落点/内容是否自洽
go run ./cmd/audio-pack -verify "..\desktop\assets\narrations-audio.zip"

# 3) 生成素材归档
go run ./cmd/assets-pack -src "data\assets" -out "..\desktop\assets\phy-assets.zip"

# 4) 构建桌面应用（-s 表示跳过前端构建，因为已手动构建）
cd ..\desktop
wails build -s -clean -platform windows/amd64
#   → build/bin/PhysicsBeauty.exe

# 5) 生成 NSIS 安装包（project.nsi 会把两个归档装到 $INSTDIR\assets）
wails build -s -nsis -platform windows/amd64
#   → build/bin/phy-beauty-amd64-installer.exe
```

> NSIS 脚本 `desktop/build/windows/installer/project.nsi` 已加入两个归档的安装指令；
> 若要发布不含音频的精简版，删掉对应 `File` 行即可（程序会正常启动，仅无现成音频）。

### 4.3.1 安装前自检（推荐）

`cmd/firstrun` 用空数据目录完整模拟一次「首次启动」，逐条核对讲解记录能否取到音频：

```powershell
cd server
go run ./cmd/firstrun -data "$env:TEMP\phy-firstrun-check"
```

输出会给出稿件入库耗时、解压文件数、幂等复跑结果、以及
「检查 9962 个文件 → 缺失 0 / 零字节 0」的结论；任一讲解找不到音频则退出码为 4。

也可以把素材归档补进**已有的**数据目录（例如旧安装包没有分发素材时的修复）：

```powershell
cd server
go run ./cmd/firstrun -data "$env:APPDATA\phy-beauty" -assets-only
```

### 4.3.2 WebView2 离线运行库与代码签名

**WebView2**：桌面端是 Wails 程序，界面靠 WebView2 渲染，所以目标机器必须有 WebView2 Runtime。
Wails 自带的四种 `-webview2` 策略（`download` / `embed` / `browser` / `error`）**都不是离线方案** ——
`embed` 也只是把 1.8 MB 的"在线版引导器"嵌进 exe，运行时仍需联网向微软下载运行库。
因此 `build-release.ps1` 默认改为分发 **Evergreen 独立安装器**：

- 构建时从 `https://go.microsoft.com/fwlink/?linkid=2124701` 取
  `MicrosoftEdgeWebView2RuntimeInstallerX64.exe`（约 **204 MB**，含完整运行库），
  缓存在 `desktop/build/windows/installer/tmp/`（该目录已被 `.gitignore` 排除）。
- 完整性判定用 **Authenticode 签名（`CN=Microsoft Corporation`）+ 体积下限**，而不是固定 SHA256：
  微软会不定期更新该链接指向的文件，钉死哈希会让之后的每次构建都失败。
- 安装时先按注册表判断是否已装（与 Wails 原宏同一个 key），**已装则完全不解压**；
  未装才把包释放到安装器的临时目录静默安装，装完即删除。
- 结果：安装包 **402 MB → 约 605 MB**。要出在线版就加 `-SkipOfflineWebView2`
  （脚本会把 `project.nsi` 还原成原宏，产物回到 402 MB）；
  内网构建机可用 `-WebView2Installer <本地文件路径>` 直接喂已下载的包。
- `project.nsi` 位于被 gitignore 的 `desktop/build/` 下，补丁由构建脚本每次重新施加并**回读校验**，
  不要手工编辑后依赖它长存。

**磁盘与内存占用**（一次完整安装）：

| 阶段 | 占用 |
|---|---|
| 下载/分发安装包 | 约 605 MB |
| 安装期间临时空间 | 约 200 MB（WebView2 包释放到安装器临时目录，装完自动删除） |
| 安装目录 `$INSTDIR` | 约 460 MB（程序 29 MB + `assets\narrations-audio.zip` 430 MB + `phy-assets.zip` 1.7 MB） |
| 首次启动解压到 `%APPDATA%\phy-beauty\audio` | 约 428 MB（10122 个文件 / 720 个目录） |
| 稳定占用合计 | 约 **890 MB**（安装包本身可删） |

**代码签名**：接口已接好，默认不签（构建末尾会打印 `signed : no`）。

```powershell
# 二选一：证书指纹（存于本机个人存储，推荐，口令不上命令行）或 PFX 文件
$env:PHY_SIGN_THUMBPRINT = 'xxxxxxxx...'
$env:PHY_SIGN_PFX = 'C:\secrets\phy-beauty.pfx'; $env:PHY_SIGN_PFX_PASSWORD = '<口令>'
.\build-release.bat
```

脚本从 Windows SDK 的 `bin\<版本>\x64\signtool.exe` 取最新版，先签 `PhysicsBeauty.exe`
（必须在 `makensis` 之前，否则装进包里的仍是未签名文件），再签安装包，
最后 `signtool verify /pa /all` 校验完整信任链，链不受信即中止发布。
**自签证书过不了 `/pa`**，也去不掉 SmartScreen 警告；它只对"把根证书批量推到受控机器"的内网部署有意义。

### 4.4 安装、升级与卸载

- **无需卸载即可重复安装**：安装程序直接覆盖旧文件，用户数据（`%APPDATA%\phy-beauty`）不受影响。重复安装**不会**重新解压音频（`.narration-audio.ok` 标记仍在），通常几秒完成。新版归档会改变标记内指纹，升级到含更多音频的安装包后首次启动会自动补齐增量部分。
- **程序运行时也能安装/卸载**：安装脚本（`EnsureAppClosed`）与卸载脚本（`un.EnsureAppClosed`）会检测 `PhysicsBeauty.exe` 是否在运行 —— 交互安装时询问用户是否自动关闭，静默模式（`/S`）下自动关闭后继续，避免 exe / 目录被占用导致失败。
- **卸载不删除用户数据**：卸载只清理安装目录与 WebView2 缓存（`%APPDATA%\phy-beauty.exe`），数据库、音频与素材保留在 `%APPDATA%\phy-beauty`，重装后直接继续使用。
- **关闭窗口即完全退出**：窗口关闭时应用会优雅关闭内嵌后端（关闭数据库连接）并结束进程，WebView2 子进程随之回收，不会在后台驻留 —— 因此重装/卸载不会被文件占用阻塞。若关闭窗口后仍看到 `PhysicsBeauty.exe`，说明该版本较早，升级到最新安装包即可。
- **需要管理员权限**：安装目录为 `Program Files`，卸载信息写入 `HKLM`。
- **断网机器也能装**：安装包内置 WebView2 离线运行库（见 §4.3.2），安装全程不需联网；安装时约需 200 MB 临时空间，装完稳定占用约 890 MB（安装目录 + 首次启动解压的音频）。
- **注意**：`project.nsi` 含中文提示，必须保存为 **UTF-8 with BOM**，否则 `makensis` 会报 `Bad text encoding`。

### 4.5 运行机制

```
WebView2 窗口
   │  所有请求 → 同一个 http.Handler（server/pkg/desktop.Handler）
   ├─ /api/*  、/audio/*  → 反向代理到进程内 Gin（127.0.0.1:<随机端口>）
   ├─ 命中内嵌静态资源    → 直接返回
   └─ 其余路径            → 回退 index.html（Angular 客户端路由）
```

由于前端与后端**同源**，生产配置里的相对路径 `/api/v1` 直接可用，无需 CORS。

## 五、数据备份与恢复

```powershell
# 备份（同时备份数据库与音频）
Copy-Item server\data\phy_beauty.db  "backup\phy_beauty-$(Get-Date -f yyyyMMdd-HHmmss).db"
Compress-Archive server\data\audio    "backup\audio-$(Get-Date -f yyyyMMdd-HHmmss).zip"

# 桌面端备份
Copy-Item "$env:APPDATA\phy-beauty" "backup\phy-beauty-appdata" -Recurse

# 恢复：停止服务 → 覆盖 db 与 audio → 启动
```

> **用户数据是资产**：任何写库操作（导入、批量生成、清理）前请先备份；测试请使用数据库副本
> （`DB_PATH` 指向副本文件 + `AUDIO_DIR` 指向临时目录）。

## 六、首次配置

1. **登录管理后台**：用 `config.yaml` 里的管理员账号（默认 `admin / admin123`）登录，进入「管理」标签。
2. **填充实验数据**：概览页「🌱 填充实验数据」（376 个实验 + 31 个分类；幂等）。
   > 桌面端安装包首次启动已自动完成讲解导入，无需手动操作。
3. **配置大模型**（需求 5）：进入「大模型配置」
   - 激活一个 `LLM` 才能生成教学内容；
   - `TTS` 可留空 —— 系统内置 **Edge TTS（免密钥）**；
   - 支持 `openai` / `azure` / `edge` / `ollama` / `custom`，同类型**只能激活一个**。
4. **补充讲解**：安装包内置音频覆盖 600 个展项 + 120 个里程碑；其余展项可在「内容生产」页生成教学内容 → 语音合成（内置 Edge TTS，免密钥）。
5. **学习进度与收藏**：普通用户注册后自动可用。

## 七、常见问题

| 现象 | 排查 |
|---|---|
| 页面空白 / 接口 404 | 确认 `STATIC_DIR` 指向 `.../browser` 目录（Angular 17 产物带 `browser/` 子目录） |
| 注册返回 500 | 老版本问题，已修复（binding tag `min:6` → `min=6`）；请更新到最新后端 |
| 首页分类为空 / 显示「未分类」 | 老版本问题，已修复（模型 json tag）；请更新后端 |
| 展项音频 404 | 确认 `AUDIO_DIR` 正确，且文件位于 `<AUDIO_DIR>/<experiment_id>/<voice>/<line_id>.mp3`；桌面端可删除 `.narration-audio.ok` 后重启以重新解压 |
| 里程碑音频 404 | 里程碑音频在 `ms<milestone_id>/` 目录（不是展项目录）；安装包需由 `cmd/audio-pack` 重新生成（旧归档按 slug 猜目录，同名 slug 会落错位置） |
| 资料页图片全部空白（404） | 素材归档未随包分发或未解压：确认 `<安装目录>\assets\phy-assets.zip` 存在，数据目录下有 `.phy-assets.ok`；旧安装可用 `go run ./cmd/firstrun -data %APPDATA%\phy-beauty -assets-only` 直接补入，或删除该标记后重启 |
| 资料页图片全空、卡片文案都在（老版本） | 桌面端只把 `/api/`、`/audio/` 反代给内嵌后端，`/phy-assets/` 落到 index.html 回退，图片拿到的是 HTML（HTTP 200 但不是图片）。已修复；旧安装需换用新的 `PhysicsBeauty.exe`。后端新增静态路由时要同步加进 `server/pkg/desktop/desktop.go` 的 `backendPrefixes` |
| 生成内容报「尚未激活 LLM」 | 在「大模型配置」激活一个 `llm` 类型模型并通过「测试」 |
| 桌面端数据丢失 | 数据在 `%APPDATA%\phy-beauty`，卸载程序不会删除该目录；可手动备份 |
| 打包报缺少 `icon.ico` | `desktop/build/windows/icon.ico` 必须存在（wails 构建需要） |
| 打包报缺少音频来源库 | 传 `-AudioDb <phy-beauty.db 路径>`，或先启动一次桌面端让库落在 `%APPDATA%\phy-beauty` |
| 安装包体积大 | 音频归档约 421 MB（9962 个文件）；如需精简可只保留单音色（体积减半）或不随包分发 |

## 八、说明：Docker 部署

架构文档 10.2 原计划提供 Docker + Nginx 方案，**本项目按需求决定不实现**。上述「三、生产部署」的单进程方式已能满足常见部署场景；如需容器化，可直接基于 `server/` 与 `client/` 两个阶段编写多阶段 `Dockerfile`。

## 九、一键打包脚本

仓库根目录提供一键构建脚本，自动完成「音频归档 → 素材归档 → 前端 → 后端 → 桌面端 → 安装包」全流程：

```powershell
# 双击运行（推荐，脚本会自动设置执行策略）
build-release.bat

# 或命令行运行并传参
powershell -NoProfile -ExecutionPolicy Bypass -File build-release.ps1
```

### 执行步骤

| 步骤 | 内容 |
|---|---|
| 1/9 | 检查工具链（go / node / npx / wails / makensis），缺失时给出安装提示并退出 |
| 2/9 | 生成讲解音频归档 `cmd/audio-pack` → `desktop/assets/narrations-audio.zip`，并 `-verify` 自检 |
| 3/9 | 生成素材归档 `cmd/assets-pack` → `desktop/assets/phy-assets.zip` |
| 4/9 | 构建前端 `npx ng build`（`node_modules` 缺失时自动执行 `npm install`） |
| 5/9 | 同步前端产物到 `desktop/frontend/dist` |
| 6/9 | 构建后端 `go build ./...`，并生成 `server/build/phy-beauty-server.exe` |
| 7/9 | 构建桌面端 `wails build -s -clean` → `desktop/build/bin/PhysicsBeauty.exe` |
| 8/9 | 编译安装包 `makensis project.nsi` → `desktop/build/bin/phy-beauty-amd64-installer.exe`，并校验安装包确实带上了两个归档（体积不小于归档本身） |
| 9/9 | 输出汇总 |

### 参数

| 参数 | 说明 |
|---|---|
| `-SkipFrontend` | 复用已有前端产物，跳过 `ng build` |
| `-SkipServer` | 不生成独立的后端可执行文件 |
| `-SkipAudioPack` | 不重新生成音频归档（复用已有的；仍会校验） |
| `-SkipAudioCheck` | 音频来源缺失时不报错（用于只做前端/安装包实验） |
| `-AudioDb <path>` | 指定用于生成音频归档的 SQLite 库（默认取 `%APPDATA%\phy-beauty\phy-beauty.db`） |
| `-AudioDir <path>` | 指定音频目录（默认 `server\data\audio`） |
| `-NoInstaller` | 只构建桌面端 exe，不生成安装包 |

```powershell
# 只重新打安装包（不重编前端与后端，但仍会重新生成并校验音频归档）
powershell -NoProfile -ExecutionPolicy Bypass -File build-release.ps1 -SkipFrontend -SkipServer

# 复用已有音频归档，只重打安装包
powershell -NoProfile -ExecutionPolicy Bypass -File build-release.ps1 -SkipFrontend -SkipServer -SkipAudioPack
```

### 脚本内的关键处理

1. **音频归档必须由库生成**：归档内 `slug → 目录` 的映射来自指定数据库，因此打包脚本先跑 `cmd/audio-pack` 再 `-verify`，避免「装了包但音频落错目录」。
2. **安装包体积校验**：安装包小于音频归档即判定归档没进包，直接失败（这正是"新机器没声音"的根因）。
3. **自动修复 `project.nsi` 的 UTF-8 BOM**：该脚本含中文提示，缺 BOM 时 `makensis` 会报 `Bad text encoding`；构建脚本在编译前自动检测并补上 BOM。
4. **不对原生命令做 `2>&1` 重定向**：Windows PowerShell 5.1 会把 `ng build` 等命令写到 stderr 的正常进度信息当作终止性错误处理。脚本只检查退出码，子进程输出直通控制台。

> 脚本与启动器全部为纯 ASCII（含注释），避免在非 UTF-8 代码页下出现编码报错。
>
> ⚠️ `wails build -clean` 会清空 `desktop/build/bin`，因此单独使用 `-NoInstaller` 时，上一次生成的安装包会被删除。

## 十、音频/素材归档工具

| 工具 | 用途 |
|---|---|
| `server/cmd/audio-pack` | 从数据库 + 音频目录生成 `narrations-audio.zip`（含 `manifest.json`）；`-verify` 只校验已有归档 |
| `server/cmd/audioaudit` | 审计「数据库讲解 vs 磁盘音频」的缺口，回答"还差多少音频要合成"（缺失时退出码 3） |
| `server/cmd/assets-pack` | 从素材目录生成 `phy-assets.zip` |
| `server/cmd/tts-gen` | 批量 TTS 合成缺失音频（内置 Edge TTS，免密钥；只补缺失文件） |
| `server/cmd/firstrun` | 空目录模拟首次启动，逐条核对讲解音频与素材是否就位 |
| `tools/audit_narration_audio.ps1` | 审计归档本身：清单完整性、落盘目录合法性、是否存在落盘冲突 |

```powershell
# 典型补音流程：先看缺口，再补，再重新打包校验
cd server
go run ./cmd/audioaudit -db "$env:APPDATA\phy-beauty\phy-beauty.db" -audio "$env:APPDATA\phy-beauty\audio"
$env:DB_PATH="$env:APPDATA\phy-beauty\phy-beauty.db"; $env:AUDIO_DIR="$env:APPDATA\phy-beauty\audio"
go run ./cmd/tts-gen -concurrency 8
go run ./cmd/audio-pack -db $env:DB_PATH -audio $env:AUDIO_DIR -out ..\desktop\assets\narrations-audio.zip
go run ./cmd/audio-pack -verify ..\desktop\assets\narrations-audio.zip
```
